# Backend Conventions

Read this document when working on the backend. Use this in conjunction with the General / Commit conventions in `CLAUDE.md`.

---

## Language & Libraries

- Go 1.22+
- Standard library first. Do not use external frameworks unless there is an explicit reason.
- HTTP routing: Use the standard `net/http` ServeMux only.

---

## Layering

- Two-layer architecture: `handler` → `repository`.
- `handler`: Responsible only for HTTP input/output. Do not write business logic here.
- `repository`: Wrap code generated by `sqlc` and expose domain-oriented methods.
- A `usecase` layer should only be added if the logic becomes complex. Do not create one for now.

---

## Error Handling

- Return early. Avoid nesting.
- Wrap errors using `fmt.Errorf("doing X: %w", err)` to maintain the error chain.
- For HTTP handlers:
  - Explicitly validate input (silent type coercion is prohibited).
  - Error responses must follow the OpenAPI `ErrorResponse` schema.
  - Do not leak internal error messages to the client.

---

## Logging

- Use `log/slog` (standard library). Do not use external logging libraries.

---

## Linting & Formatting

- Format with `gofmt`.
- Lint with `golangci-lint` (default settings).
- Always execute before committing.
